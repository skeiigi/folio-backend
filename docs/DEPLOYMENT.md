# Размещение API отдельно от интерфейса

1. Создайте управляемую базу PostgreSQL и сохраните строку подключения. API является единственным клиентом базы: строка `DATABASE_URL` никогда не передаётся React/Vercel.
2. В Render создайте Web Service из этого репозитория или примените `render.yaml`. Сборка: `npm ci`. Команда запуска: `npm run db:migrate && npm start`. Health check: `/ready`. Используйте Node.js 22.
3. Установите переменные: `NODE_ENV=production`, `DATABASE_URL`, `JWT_SECRET` (случайные 32+ символа), `CORS_ORIGINS=https://<точный-домен-фронтенда>`, `STORAGE_DRIVER=postgres`. Установка `DB_MODE=postgres` рекомендуется явно. Не включайте демонстрационное сидирование в команду запуска.
4. После публикации API скопируйте его HTTPS-адрес в переменную интерфейса `VITE_API_URL=https://<API-домен>/api/v1` и соберите фронтенд. Добавьте его фактический HTTPS origin в `CORS_ORIGINS` и перезапустите API. В переменной перечисляются полные origins через запятую, без конечного `/`.
5. Проверьте `/ready`, регистрацию, публикацию работы, загрузку и повторное чтение файла после перезапуска API, отправку брифа и приватность референсов.

Дополнительные настройки:

| Переменная | Назначение |
| --- | --- |
| `PORT` | Порт HTTP; хостинг обычно задаёт сам |
| `MAX_UPLOAD_MB` | Максимальный размер файла; по умолчанию 20 МБ |
| `STORAGE_DRIVER=s3` | Вместо PostgreSQL использовать S3-совместимое объектное хранилище |
| `S3_ENDPOINT`, `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Параметры S3; значения нужны только при `STORAGE_DRIVER=s3` |
| `RESEND_API_KEY`, `MAIL_FROM` | Включают доставку уведомлений о новых брифах по email |
| `CRM_WEBHOOK_URL`, `BPMS_WEBHOOK_URL`, `WEBHOOK_SECRET` | Включают подписанные HTTPS-события для внешних систем. Секрет не короче 32 символов |

Секреты задаются в настройках хостинга и не коммитятся в Git. `.env.example` содержит только образец. Если ожидаются большие или многочисленные файлы, используйте S3: хранение бинарных данных в PostgreSQL удобно для учебного MVP, но увеличивает объём БД. Миграция запускается при каждом старте идемпотентно. Резервное копирование базы и S3 настраивается у выбранных провайдеров отдельно.

Бесплатные тарифы провайдеров, сон сервиса и квоты могут меняться. `render.yaml` задаёт бесплатный план, но база создаётся отдельно. Фронтенд поддерживает Vercel и Netlify; собственный постоянный URL появляется только после подключения этих сервисов владельцем аккаунта.
